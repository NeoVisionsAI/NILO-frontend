# Imagen Docker del frontend en GHCR

El **frontend** se publica como imagen en **GitHub Container Registry**:

```text
ghcr.io/neovisionsai/nilo-frontend:<tag>
```

(`neovisionsai` en minúsculas; org GitHub `NeoVisionsAI`.)

La imagen incluye el build estático (Vite) servido por **nginx** con HTTPS (certificados montados en runtime desde el host).

---

## 1. Publicar (CI automático)

Al hacer **push** a `main` o `master`, el workflow [`.github/workflows/publish-ghcr.yml`](../.github/workflows/publish-ghcr.yml) construye y sube la imagen.

| Tag | Cuándo |
|-----|--------|
| `latest` | último commit en la rama por defecto |
| `main` | push a `main` |
| `<sha>` | commit concreto |
| `v1.0.0` | tag git `v*` |

Manual: **Actions → Publish frontend image (GHCR) → Run workflow**.

**Build-time (Vite):** `VITE_API_BASE_URL`, `VITE_API_DIRECT`, `VITE_APP_NAME`, `VITE_CARDMED_PROVISIONING_MODE`.  
Opcional: variables de repositorio en GitHub (`Settings → Secrets and variables → Actions → Variables`).

---

## 2. Visibilidad del paquete

Repo público **≠** paquete GHCR público.

Tras el primer workflow OK:

**GitHub → Packages → nilo-frontend → Package settings → Change visibility → Public**

Si es privado, en cada servidor:

```bash
echo "$GITHUB_TOKEN" | docker login ghcr.io -u TU_USUARIO --password-stdin
```

(PAT con `read:packages`. Sin login: `unauthorized` en `docker pull`.)

## 3. Desplegar en VM sin clonar el repo

Bundle en [`deploy/vm-ghcr/`](../deploy/vm-ghcr/).

### Primera vez (Ubuntu)

```bash
sudo apt update && sudo apt install -y docker.io docker-compose-plugin curl
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
# cerrar sesión SSH y volver a entrar

mkdir -p ~/nilo-frontend && cd ~/nilo-frontend
curl -fsSL https://raw.githubusercontent.com/NeoVisionsAI/NILO-frontend/main/deploy/vm-ghcr/bootstrap.sh | bash

cp credentials.env.example credentials.env
# editar BACKEND_PROXY_HOST, BACKEND_PORT, FRONTEND_SSL_PORT…

mkdir -p certs
# cert.pem + key.pem (mkcert en dev o copiar; ver certs/README.md)

docker login ghcr.io   # si paquete privado
chmod +x deploy.sh
./deploy.sh
sudo ./deploy.sh --install-systemd   # opcional
```

URL: **https://&lt;IP&gt;:8080/login** (solo HTTPS en ese puerto).

### Cada actualización de código

```bash
cd ~/nilo-frontend
./deploy.sh
```

No hace falta `bootstrap.sh` salvo que cambien scripts de despliegue en el repo.

## 4. Build y push manual

```bash
export IMAGE=ghcr.io/neovisionsai/nilo-frontend
export TAG=latest

echo "$GITHUB_TOKEN" | docker login ghcr.io -u TU_USUARIO --password-stdin

docker build \
  --build-arg VITE_API_BASE_URL=https://192.168.1.43:8443/api/v1 \
  --build-arg VITE_API_DIRECT=false \
  -t "$IMAGE:$TAG" .

docker push "$IMAGE:$TAG"
```

## 5. Integración con NILO-backend

| Componente | Configuración |
|------------|----------------|
| Frontend → API | Por defecto: mismo origen `https://IP:8080/api/v1` (proxy nginx). Vars en `credentials.env`: `BACKEND_PROXY_*`. |
| Backend CORS | `CORS_ORIGINS` debe incluir `https://<IP>:8080` (o el host real). |
| API en `:8001` HTTP | Valorar `VITE_API_DIRECT=true` en build de imagen + URL directa, o terminar TLS en nginx hacia backend. |

Backend GHCR: `ghcr.io/neovisionsai/nilo-backend:latest` — ver `NILO-backend/docs/07.ghcr_deploy.md`.

## 6. Desarrollo local vs producción GHCR

| Entorno | Comando |
|---------|---------|
| Dev (repo clonado) | `./deploy.sh --rebuild` o `./deploy.sh --dev` |
| VM producción (sin repo) | `deploy/vm-ghcr/deploy.sh` tras `bootstrap.sh` |
