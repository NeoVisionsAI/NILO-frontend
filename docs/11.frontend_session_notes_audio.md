# Frontend: notas de texto y audio en sesión

Base URL API (ejemplo producción):

```text
https://nilomed.eu/api/v1
```

En desarrollo LAN suele resolverse vía proxy same-origin (`/api/v1`) desde el frontend HTTPS.

Todas las rutas requieren header:

```text
Authorization: Bearer <access_token>
```

Referencia backend: `NILO-backend/docs/11.frontend_session_notes_audio.md`  
Sesiones: `NILO-backend/docs/04.monitoring_sessions.md`

## 1. Nota de texto (solo MongoDB, sin MinIO)

Texto clínico asociado a una sesión. El cuerpo se guarda cifrado en la base de datos.

### Crear nota

```http
POST /sessions/{session_id}/text-notes
Content-Type: application/json
```

Cuerpo:

```json
{
  "patient_id": "675abc...",
  "node_id": "675node...",
  "body": "Paciente estable, sin incidencias en la última hora.",
  "recorded_at": "2026-11-24T14:30:00Z"
}
```

- `patient_id` obligatorio; debe coincidir con la sesión.
- `node_id` opcional; si la sesión tiene nodo, debe coincidir si se envía.
- `body` obligatorio (1–20000 caracteres).
- `recorded_at` opcional (UTC); por defecto, ahora.

Respuesta **201**: objeto `SessionTextNoteOut` (`id`, `session_id`, `body`, `author_id`, `recorded_at`, …).

Permisos: **staff** (clinician/root).

La sesión puede estar **activa o cerrada** (no hace falta que siga activa para anotar).

### Listar notas de una sesión

```http
GET /sessions/{session_id}/text-notes?skip=0&limit=100
```

Respuesta: array de notas, más recientes primero.

### Editar texto

```http
PATCH /sessions/{session_id}/text-notes/{note_id}
Content-Type: application/json

{ "body": "Texto corregido." }
```

### Resumen de sesión

`GET /sessions/{session_id}/overview` incluye el campo `text_notes` (conteo).

## 2. Nota de audio (MinIO + MongoDB)

Flujo presigned: metadatos en API, binario directo a MinIO.

1. `POST /audio` con `"kind": "voice_note"`, `session_id`, `patient_id`, `start_ts`, etc. → `upload_url`
2. `PUT {upload_url}` con el binario del audio
3. `POST /audio/{audio_id}/confirm`
4. Tras subir (`POST /audio/upload` con `kind=voice_note`), el front llama `POST /audio/{audio_id}/transcribe` (staff; puede tardar ~1 min en CPU).
5. Corrección manual: `PATCH /audio/{audio_id}/transcription` con `{ transcription, transcription_status: "done" }`.

En `AudioOut`: `transcription` (string | null), `transcription_status`: `none` | `pending` | `done` | `failed`.

**Sesión debe estar activa** para ingestar audio (a diferencia del texto).

Listar: `GET /audio?patient_id=...&session_id=...`

## Comparación rápida

| | Nota texto | Nota audio |
|--|------------|------------|
| Ruta principal | `POST .../sessions/{id}/text-notes` | `POST /audio` + PUT + confirm |
| Almacenamiento | MongoDB | MinIO + metadatos MongoDB |
| Sesión activa | No obligatorio | Sí (ingesta) |
| Rol crear | staff | staff |

## Uso con el cliente NILO-frontend

El proyecto ya centraliza llamadas en `src/services/api.ts` (`api.post`, `api.get`, …).

Ejemplo nota de texto:

```typescript
import { api } from '@/services/api'

await api.post(`/sessions/${sessionId}/text-notes`, {
  patient_id: patientId,
  node_id: nodeId ?? undefined,
  body: 'Nota clínica…',
})
```

Para **audio**, el `PUT` a `upload_url` es a **MinIO** (otro origen): usar `fetch(upload_url, { method: 'PUT', body: blob, headers: { 'Content-Type': 'audio/wav' } })` **sin** el Bearer de NILO (URL presignada).

## Estado en la UI (frontend)

Implementado en ficha de paciente (FAB → **Nota de texto** / **Nota de audio**):

| Pieza | Ruta |
|-------|------|
| Servicios | `clinical-patient.service.ts`, `monitoring-session.service.ts`, `audio-recording.service.ts` |
| Tipos | `src/types/monitoring-session.ts` |
| UI | `TextNoteCondata.tsx`, `AudioNoteCondata.tsx` (selector de sesión, lista, alta, detalle) |
| Cableado | `PatientDetailPage.tsx` → `openModule` |

Flujo:

1. `GET /patients` → resuelve `patient_id` clínico por `user_id` (id del usuario de la ficha).
2. `GET /sessions?patient_id=…` + **Nueva sesión** (`POST /sessions`).
3. Texto: `GET/POST/PATCH …/text-notes` por sesión seleccionada.
4. Audio (sesión **activa**): grabación → `POST /audio/upload` (o flujo presign legacy); tras subir, `POST …/transcribe` automático; detalle/edición con `VoiceNoteTranscriptBlock` y `PATCH …/transcription`. En **Explorar → Notas voz**, texto bajo la onda + «Generar transcripción» si falta.
