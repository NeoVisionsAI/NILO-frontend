# Monitorización ↔ sesión activa

## Comportamiento clínico

- Con **monitorización inactiva** no debe haber ingestión ni sesión abierta.
- Al **activar** monitorización:
  1. Crear `MonitoringSession` (`POST /sessions`) con `patient_id` clínico, `node_id` si aplica y `external_session_id` (UUID visible para el usuario / nilo-node).
  2. Los binarios en MinIO usan rutas bajo `patients/<clinical_patient_id>/…/<session_id>/…` en el primer upload (no hace falta carpeta previa; opcional marcador `.session` en backend).
  3. Marcar `monitoring_active: true` en el usuario paciente.

- Al **desactivar**:
  1. `POST /sessions/{id}/end`
  2. `monitoring_active: false` y limpiar referencia a la sesión abierta.

## Frontend (implementado)

- Servicio: `src/services/patient-monitoring.service.ts`
- Contexto: `setPatientMonitoring()` en `ClinicalDataContext`
- Ficha paciente: toggle llama a start/stop; muestra UUID (`external_session_id`) y referencia corta del id Mongo.

## Backend recomendado (pendiente en API)

Para que el nodo y otros clientes no dependan solo del frontend:

| Campo | Dónde | Uso |
|-------|--------|-----|
| `patient_profile.active_session_id` | `User` | Id de sesión abierta mientras `monitoring_active` |
| `active_session_id` | `Patient` clínico | Mismo valor, sincronizado |
| `POST /users/{id}/monitoring/start` | API | Crear sesión + flags atómicamente |
| `POST /users/{id}/monitoring/stop` | API | Cerrar sesión + flags |

Hasta entonces el frontend crea/cierra sesión y solo persiste `monitoring_active` vía `PATCH /users/{id}`.
